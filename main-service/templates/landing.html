Go Echo Microservices Demo

Multi-Service Architecture with Nginx & Docker

A practical demonstration of how to build, route, and deploy multiple Go Echo services behind an Nginx reverse proxy, all containerized with Docker Compose.

Architecture Overview

Clientbrowser / curl
→
Nginx:8080 reverse proxy
→
main-service:8081 Echo
→
items-service:8082 Echo

Nginx inspects the path prefix and routes /main/ or /items/ to the appropriate backend. Each service runs in its own container with no public port exposure — only Nginx faces the outside world.

Services

🔒 main-service :8081

Authentication and user management. Handles JWT-based sign-in, token validation middleware, and user profile lookups. Acts as the identity provider for other services.

Tech: Echo v4, golang-jwt/v5, Swagger (swaggo)

📦 items-service :8082

CRUD operations for items. Communicates with main-service via REST to validate tokens and resolve user information. Demonstrates inter-service communication patterns.

Tech: Echo v4, godotenv, Swagger (swaggo)

Nginx Configuration

The reverse proxy does path-based routing. Nginx strips the prefix and forwards to the correct service. Each service also exposes interactive Swagger API docs through the proxy. 

server {
    listen 8080;

    location / {
        proxy_pass http://main-service:8081/;
    }

    location /main/ {
        proxy_pass http://main-service:8081/;
        proxy_redirect /swagger/ /main/swagger/index.html;
    }

    location /items/ {
        proxy_pass http://items-service:8082/;
        proxy_redirect /swagger/ /items/swagger/index.html;
    }
}

ⓘ Service hostnames (main-service, items-service) are resolved automatically via Docker Compose’s internal DNS. No hardcoded IPs needed.

Docker Compose

All three containers (Nginx + two Go services) are defined in a single compose file. Each Go service uses a multi-stage Dockerfile to produce a tiny Alpine-based image. 

services:
  nginx:
    image: nginx:latest
    ports: ["8080:8080"]
    volumes: ["./nginx/nginx.conf:/etc/nginx/nginx.conf:ro"]
    depends_on: [main-service, items-service]

  main-service:
    build: { context: ./main-service, target: runtime }
    expose: ["8081"]

  items-service:
    build: { context: ./items-service, target: runtime }
    expose: ["8082"]

Getting Started

Build and run the entire stack with a single command (uses Podman, see Makefile for Docker equivalents): 

make rebuild

This builds the Go binaries inside Docker, creates the three containers, and starts everything. Once running, open http://localhost:8080 in your browser to see this page. The services are also available directly (without Nginx) for debugging: 

# Main service
curl http://localhost:8080/main/api/v1/auth/signin \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"admin123"}'

# Items service
curl http://localhost:8080/items/api/v1/items
